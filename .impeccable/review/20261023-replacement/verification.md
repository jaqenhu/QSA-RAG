# 更换待填表后的数据同步整改

日期：2026-10-23（Asia/Shanghai）。

## 已确认的问题

- 浏览器复现：相同字节的文件改名上传后，接口复用旧输入 ID 与旧文件名，页面仍显示 `input.xlsx` 而非选择的新文件名。
- 接口回归复现：更换为不同工作表、不同问题的新文件后，`/api/assessment/current` 仍返回上一输入的任务。
- 代码确认：上传成功没有清空旧任务；加载与进度轮询的异步响应缺少输入/任务身份校验，旧响应可能覆盖新工作区。
- 文件名、工作表摘要、生成进度、待填表明细、自评说明预览均依赖上述共享状态，因此在相应换表场景受到影响。

## 修复

- 每次成功上传保留新的输入记录与原始副本，包括同名重传、相同内容改名；历史输入名称与生成结果不修改。
- 当前任务查询限定到当前输入，按创建顺序恢复该输入最新且未删除的任务。
- 上传成功清空旧任务、进度浮层内容、选中项、筛选及搜索，统一从新解析结果重建工作表摘要、明细、预览和证据面板。
- 上传和新建任务使旧加载请求失效；轮询响应与错误均核对工作区请求序号、输入 ID 与任务 ID，旧响应不再更新状态或安排后续轮询。
- 上传失败保留此前有效输入；历史任务只读和生成期间禁止换表的限制继续生效。

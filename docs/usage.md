# 使用与部署说明

[← 返回 README](../README.md)

## 运行环境

- Windows 当前用户环境，Node.js ≥24、Python ≥3.10。
- Python 依赖为 `openpyxl` 和 `defusedxml`，由 `requirements.txt` 安装。
- 数据使用 Node.js 内置 SQLite，无需单独安装数据库或 Microsoft Excel。
- 模型通过 API 调用，本机无需独立显卡；完整离线模型部署不在当前验证范围内。
- 服务仅供本机浏览器访问，无需账号或密码；尚无多人任务隔离或排队。

首次安装与启动见 [快速开始](../README.md#快速开始)。建议用普通 Windows 用户终端运行；API Key 使用当前用户的 DPAPI 加密。

### 日常启动

部署完成后，双击项目根目录的 **`start.cmd`**。脚本自动定位项目目录，优先使用 `QSA_PYTHON` 指定的解释器，其次尝试 `.venv`、`python` 和 Windows 的 `py -3`；检查运行环境与依赖后启动服务，并自动打开浏览器。

保持窗口开启。输入 `q` 并回车，或按 `Ctrl+C`，等待服务停止后再关闭窗口。启动失败会保留错误提示，不会自动安装软件、关闭已有服务或修改系统设置。支持已有的 `PORT`、`QSA_DATA_DIR` 配置；设置 `QSA_NO_BROWSER=1` 可关闭自动打开浏览器。

如需手动启动：

在项目目录打开 PowerShell，每次新开终端时指定项目虚拟环境中的 Python：

```powershell
$env:QSA_PYTHON = (Resolve-Path '.\.venv\Scripts\python.exe').Path
npm run dev
```

保持窗口开启，停止服务时按 `Ctrl+C`。当前项目没有自动安装后台进程或开机启动项。

### 可选配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4174` | HTTP 端口；占用时可改为 `4175` 等空闲端口 |
| `QSA_PYTHON` | `python` | Python 可执行文件，推荐使用项目虚拟环境中的绝对路径 |
| `QSA_DATA_DIR` | 项目内 `.data/` | 业务数据目录，建议指定绝对路径 |

变量在启动前设置，例如 `$env:PORT = '4175'`。服务实际地址以终端输出为准。同一数据目录只允许启动一个服务，即使端口不同也不能重复运行。

当前监听地址固定为 `127.0.0.1`，并校验 Host 与 Origin。局域网访问需另行配置 HTTPS、可信地址及防火墙，不能只修改监听地址。直接双击 `index.html` 无法使用业务接口，GitHub Pages 也不能运行本项目的 Node.js/Python 后端。

## 首次使用

1. 打开本机地址，直接进入工作台，无需注册或登录。
2. 在“模型配置”添加生成模型和向量模型，填写服务商提供的 API 地址、模型 ID 和 API Key，保存后执行连接测试。重排模型可选。
3. 导入知识库 `.xlsx`，核对预览后确认发布；在“知识库训练”选择工作表和已通过测试的向量模型，建立索引。
4. 在“检索验证”输入真实审核问题，检查是否找到合适的原文及来源，再开始填表。
5. 上传待填表，核对工作表和问题行；先选择“前 5 项”验证，确认后再处理全部问题。
6. 审核结果，按需重试失败项，再导出新 Excel 副本。历史任务可只读回看与导出。

### 模型服务

当前真实云端验证覆盖阿里云百炼，曾验证 `qwen-max`、`text-embedding-v4`（1024 维）及 `qwen3-rerank`。这是既有验证记录，模型当前可用性和权限以服务商控制台为准；其他服务商入口尚未逐项实测。

API 地址与 Key 必须属于相同地域或业务空间。百炼可使用控制台提供的兼容接口地址；生成、向量与重排需分别配置正确类型。Key 仅在本机页面填写，接口不回显密钥或密文。

数据保存在本机；向量化会向所配服务发送所选问答的章节、问题和 C 列说明，生成与重排会发送当前问题及候选知识问答，不发送完整原 Excel 文件或 D 列旧备注。云模型调用需要联网，并使用相应服务商额度。

## Excel 与结果规则

| 项目 | 规则 |
| --- | --- |
| 格式 | `.xlsx`，单文件不超过 20 MB |
| 知识来源 | B 列为问题，C 列为自评说明；D 列旧备注不参与判断 |
| 待填表 | 按 B 列逐题定位 C 列；最多 5,000 项，超过需拆分 |
| 来源定位 | 保留工作表、原始行号及引用片段 |
| 答案生成 | 模型选择依据，程序核验引用后组合 C 列原文片段；缺失依据明确列出 |
| 导出 | 生成副本；C 列写自评说明，新增 D 列依据、E 列详细说明及原有列之后的来源列，原 D 列起的附加列右移两列 |

网页与导出结果区分“可直接复用”“部分有依据”“无相关信息”和“调用失败”。已知的引用校验、网络连接和超时故障会进一步显示具体原因。“无相关信息”是完成判断，不能与调用失败混为一谈；进度达到 100% 也不代表答案全部正确。

最多同时处理两题，结果逐题保存。可停止任务或创建新的失败项重试；服务重启不会自动恢复云端调用。刷新可恢复当前任务显示。

导出仅拆涉及问题的 C 列纵向合并，保留源文件。宏、加密、受保护的待填工作表、跨越 C 列与其他列的答案合并，以及部分复杂公式、图表和结构化表组合会明确拒绝。输出仍需人工核对，不替代证据适用性审核。

## 检索与索引

支持关键词、向量、混合检索，以及可选重排。默认使用向量/BM25 各召回 20 条、RRF k=60、最多重排 40 条、返回最多 8 条、重排阈值 0.5。分数和阈值不表示事实正确率。

正式参数在“知识库训练 → 检索设置”中保存；“检索验证”里的临时参数不会自动替换正式设置。自评任务冻结启动时的检索参数，后续修改不影响运行中的任务。

知识库版本更新可复用内容未变的向量；更换向量模型、维度或解析规则时需重建。索引只有通过校验才发布，取消或失败不会替换已有可用索引。缺少 C 列说明的知识条目保留，但不参与索引。

## 数据、备份与迁移

默认目录为 `.data/`：

```text
.data/
├── qsa.sqlite   # 模型配置、知识、索引和任务历史
└── files/       # 上传的 Excel 副本
```

模型配置存于数据库的 `model_configs` 表，API Key 为 DPAPI 密文。启动时会清理旧版本的账号、会话、登录限流和认证审计表，保留业务数据及 API Key 密文；原有备份不会被修改。

**备份前等待任务结束并关闭服务，然后复制完整 `.data/`；恢复时同样先关闭服务，再恢复完整目录。** 不要只复制正在使用的数据库文件。

换电脑或 Windows 用户后，业务数据可保留，但模型 API Key 需要重新填写并测试，因为原密文绑定原 Windows 用户和机器。运行环境和依赖也需要在新设备重新安装。

`.gitignore` 排除了 `.data/`、备份、验收资料、虚拟环境、依赖和环境配置文件。自定义 `QSA_DATA_DIR` 时需另外确认其不会被提交；GitHub 网页手动上传也需自行排除业务数据。忽略规则不会自动移除已跟踪文件或清除历史提交。

## 开发验证

在已安装项目依赖且 Python 可用的环境运行：

```powershell
$env:PATH = (Resolve-Path '.\.venv\Scripts').Path + ';' + $env:PATH
npm run check
npm test
```

第一行让当前终端的 `python` 指向已安装依赖的项目虚拟环境；如使用其他 Python 环境，需确保已安装 `requirements.txt`。自动测试使用隔离临时数据和模拟模型服务，不修改真实知识库或调用云模型。

浏览器验证脚本位于 `tests/*browser-smoke.mjs`，额外需要 Playwright 与本机 Edge，可通过 `QSA_PLAYWRIGHT_MODULE` 指定现有 Playwright 模块的 `index.mjs`。它们不属于 `npm test` 的默认执行范围。
